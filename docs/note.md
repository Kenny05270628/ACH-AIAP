# **智能面试辅助平台项目大纲**

## 一、项目概述
开发一个面向求职者的 **智能面试辅助平台**，核心功能包括：
- **简历智能分析**：自动解析简历内容，评估质量，提出优化建议。
- **AI模拟面试**：基于岗位要求，生成结构化/行为面试问题，进行语音或文本交互式模拟面试，并提供反馈。
- **个性化推荐**：根据用户背景推荐岗位、面试题库、技能提升建议。

目标用户：应届毕业生、职场转型者、希望提升面试表现的求职者、HR/招聘人员、培训机构。

### 用户角色与使用场景
| 用户角色 | 使用场景 |
|---------|---------|
| 求职者 | 上传简历获取分析建议，进行模拟面试练习 |
| HR/招聘人员 | 批量分析简历，评估候选人能力 |
| 培训机构 | 提供面试培训服务，管理知识库资源 |

---

## 二、核心功能模块

### 1. 用户系统
- 注册/登录（邮箱+密码 or OAuth）
- 简历上传与管理
- 面试记录与历史回放

### 2. 简历智能分析模块
- 简历解析（PDF/DOCX → 结构化数据）
- 关键词提取（技能、项目、教育经历等）
- 与目标岗位 JD 对比，计算匹配度
- 输出优化建议（如“缺少量化成果”、“技能关键词不足”）

### 3. AI 模拟面试模块
- 岗位选择 → 自动生成面试题（技术/HR/行为）
- 支持 **文本输入** 或 **语音输入（可选）**
- 调用大模型（如通义千问）评估回答质量
- 生成反馈：内容完整性、逻辑性、关键词覆盖、语言表达

### 4. 面试知识库与岗位数据
- 内置常见岗位（软件工程师、数据分析师等）的面试题库
- 支持用户自定义岗位描述（JD）用于定制化模拟

## 三、技术选型分析

| 组件 | 选型 | 理由 |
|------|------|------|
| 后端框架 | **FastAPI** | 异步支持好、自动生成 OpenAPI、类型安全、适合 AI 服务 |
| 前端 | **Streamlit** | 快速构建 AI 应用原型，支持文件上传、交互控件，适合 MVP |
| 主数据库 | **PostgreSQL** | 关系型数据（用户、简历元数据、面试记录）存储可靠 |
| 缓存/会话 | **Redis** | 存储会话状态、临时面试上下文、限流控制 |
| 大模型服务 | **通义千问 API（Qwen）** | 中文理解强，支持 prompt 工程、评分、建议生成 |
| 文件存储 | **建议加入 S3 / MinIO / 阿里 OSS** | 存储用户上传的简历文件（PDF/DOCX），解耦数据库 |
| 向量检索（可选） | **pgvector + PostgreSQL** | 若需实现“相似简历推荐”或“基于语义的岗位匹配”，则需向量化存储与检索 |

## 四、是否需要 pgvector 和 S3？

### ✅ **建议加入 S3（或兼容对象存储）**
- **理由**：简历文件（PDF/DOCX）不宜存入数据库，应使用对象存储。
- **实现方式**：用户上传 → 临时保存 → 解析后存元数据到 PostgreSQL，原始文件存 S3，返回 URL。
- **替代方案**：本地存储（仅限开发/测试），不推荐生产环境。

### ✅ **pgvector 视需求而定**
- **若仅做规则匹配 + 大模型分析**：**可暂不引入**，用通义千问直接做语义理解即可。
- **若需以下功能，则强烈建议引入**：
  - “找出与你背景相似的成功简历”
  - “根据简历语义推荐最匹配岗位”
  - “面试问题个性化推荐（基于历史回答向量）”
- **实现方式**：将简历/岗位描述嵌入为向量（可用 Qwen-Embedding 或 text-embedding 模型），存入 pgvector。

> 💡 初期 MVP 可先不用 pgvector，后期通过插件式扩展加入。

## 五、系统架构图（文字版）

```
[Streamlit 前端]
     ↓ (HTTP / 文件上传)
[FastAPI 后端]
     ├── 用户认证 → Redis（会话）
     ├── 简历上传 → S3（存文件） + PostgreSQL（存元数据）
     ├── 简历解析 → 使用 python-docx / pdfplumber / unstructured
     ├── 调用 Qwen API → 分析简历 / 生成面试题 / 评估回答
     └── （可选）pgvector → 存储嵌入向量，用于语义检索
```

## 六、关键技术点与挑战

| 挑战 | 解决方案 |
|------|--------|
| 简历格式多样（PDF/DOCX） | 使用 `unstructured` + `pdfplumber` + `python-docx` 组合解析 |
| 大模型调用成本与延迟 | 缓存常见回答、设置 token 限制、异步调用 |
| 面试反馈的可信度 | 设计结构化 prompt（如：“请从逻辑性、专业性、完整性三方面打分并说明”） |
| 多轮面试上下文管理 | 用 Redis 存储对话历史（user_id → conversation history） |
| 隐私与数据安全 | 敏感信息脱敏、文件加密存储、API 调用日志审计 |

---

## 七、MVP 开发路线建议

1. **第1周**：搭建 FastAPI + Streamlit 基础框架，实现用户上传简历（PDF/DOCX）。
2. **第2周**：集成简历解析 + 调用通义千问生成初步分析报告。
3. **第3周**：实现岗位选择 + AI 面试问题生成 + 文本回答评估。
4. **第4周**：加入 PostgreSQL 存储用户数据，Redis 缓存会话。
5. **第5周+**：优化 UI/UX，加入历史记录、建议导出 PDF 等。
6. **后期扩展**：引入 S3、pgvector、语音识别（Whisper）、打分可视化等。

## 八、推荐工具与库

- 简历解析：`unstructured`, `pdfplumber`, `python-docx`
- 向量化（若用）：`dashscope`（通义千问 Embedding API）或 `sentence-transformers`
- 文件存储 SDK：`boto3`（兼容 S3）
- 异步任务：`celery`（如需后台解析）
- 日志监控：`structlog` + `Prometheus`
